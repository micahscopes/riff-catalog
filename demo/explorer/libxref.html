libxref facet names-blind · unit yul-fn · the chunks devs actually import

Developers know these primitives by name. The compiler turns each into a Yul function; riffcat fingerprints it names-blind. Two facts fall out: within one library the chunk is one fingerprint across every contract that vendors it — and the same primitive in a different library is a different fingerprint. So shape alone tells you which library a contract pulled from. The supply chain is in the fingerprint.

Locally compiled, verbatim OpenZeppelin v4.9 / Solady / Solmate source, solc 0.8.33 via-IR, unoptimized. Each primitive is vendored by three genuinely different consumer contracts (Vault / Airdrop / Lottery); the fingerprint shown is the structure facet of the generated yul-fn unit. The chunk's fingerprint is source-determined, so it matches what a mainnet contract using the same library version produces — the method scales to any Sourcify-verified contract (cf. the Seaport beat).
